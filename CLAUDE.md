# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

An incremental/idle game about elevators (Godot 4.7, GDScript), built for **iPhone via GitHub Pages**. The primary target is the **threadless web export** — Pages cannot set the COOP/COEP headers Godot's threaded export needs. Anything added must work in mobile Safari and fit a 393pt-wide phone.

Two files are authoritative about what exists and why. **Read them before designing or editing:**
- `docs/superpowers/specs/2026-08-01-elevator-incremental-design.md` — the base design (some sections are out of date; the UI spec's §9 lists what).
- `docs/superpowers/specs/2026-08-02-ui-design.md` — current UI design (coords §3, ghost floor/shaft §3.4, input §4, verification §8).

Implementation plans and handoffs live in `docs/superpowers/plans/` (`HANDOFF.md` is a template for fresh sessions).

## Commands

```sh
godot                                # open editor
godot --headless --import            # import assets (×2 in CI)
godot --headless --export-release "Web" build/web/index.html   # web build
godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit   # run the whole GUT suite
```

- **Run a single test file:** `godot --headless -s addons/gut/gut_cmdln.gd -gtest=res://tests/test_tenancy.gd -gexit` — **`-gdir` takes a directory, not a file.**
- **Run one named test:** add `-gunit_test_name=test_name`. There is no `-ginclude`.
- The `-gdir=<file>` / `-ginclude` forms print `[GUT ERROR] Nothing was run` and **exit 0** — a false green before a commit. Measured 2026-08-03 on GUT 9.7.1.
- **CI** (`.github/workflows/deploy.yml`): on push to `main` — install Godot 4.7 → run GUT → assert threadless export → build → deploy to Pages. Local GUT must pass before merging.
- **Dev-only override:** `godot -- --board=40x8` starts an oversized board for screenshots. Do not let this pattern into a shipped default.

## Architecture

Three hard-separated layers, sealed by the rule "sim never touches the scene tree":

```
data/ (JSON)  →  sim/ (pure RefCounted logic)  →  game/game_root.gd (the one owner)  →  view/ + ui/ (Nodes)
```

- **`sim/`**: all game logic, `extends RefCounted`, **no Nodes, no FileAccess**. Unit-tested headlessly via GUT. Talks upward only by signals emitted from `GameState`.
- **`data/`**: numeric coefficients (JSON) loaded at runtime. Never expression strings — running stored formulas is an eval.
- **`game/game_root.gd`** (entry: `game/game_root.tscn`) is the single owner: pumps the sim, saves, binds views. **Views never mutate logic**; they read state and emit signals.
- **view/ + ui/**: `Control` nodes that render sim state. Touching sim state from a view is a layering violation.

**The sim tick runs in a fixed, written order that is player-visible** (determinism + behavior depend on it):
`metrics.advance → spawn → move/doors → deliver → auto-dispatch → expire → tenancy → note_ticks`
Most important boundary: **deliver runs before expire**, so a passenger reaching exactly 0 patience as the doors open is delivered. Tests pin these orderings and cross-module invariants (e.g. `ElevatorCar.floors_per_tick` must equal `Upgrades.SPEED_BASE`) on purpose — do not weaken them.

The sim runs at **20 Hz** (SimClock accumulates Godot's default 60 Hz).

Core design invariants baked into the sim (see their docstrings):
- **No fail state** — cash floors at 0 (no debt); re-leasing is free while fewer than 2 floors are tenanted so a stranded player can always recover.
- **Rent is dead.** ALL money comes from moving people. A tenant's only value is the traffic it generates, so losing a tenant costs you that floor's fares.
- **Income to a floor is credited to the floor that *generated* the trip (`Passenger.source_floor`), not the endpoint** — under directional traffic most trips have the lobby at one end.

## Details

Per-module maps are generated and held in **`codemaps/`** (`architecture.md`, `sim.md`, `view.md`, `data.md`, `tests.md`) — read those for per-file APIs, constants, and the test↔module map. They are regenerated by `/cc-codemaps:update-codemaps`; user edits there will be overwritten, so keep project notes here instead.

**Status:** Milestones 1–3, the board/management UI, the cost-curve work, Spec A
(tenant kinds + floor class) and **S5 (prestige)** are built and tested.

S5 in one paragraph: a run now caps at **10 floors** and ladders to 20 through
the `height` node. `sim/meta.gd` owns the persistent tree (Blueprints, node
levels, and the derivations a run starts from) and `sim/prestige.gd` owns the
demolish, which **builds a fresh `GameState` against a cloned Meta** rather than
wiping the live one. Save format is **v4**: the tree rides in the same file as
the run, because a demolish must persist both in one write. `data/blueprints.json`
is fatal-if-malformed, exactly like `data/tenants.json`.

**Shafts are gated twice, on purpose (2026-08-04).** They are bought with cash
inside a run *and* bounded by `Meta.shaft_cap()` — 2 on a first run, laddering
2/4/6/8 through the `shafts` node. The node used to grant a free *starting*
shaft per level, which made the cash price stop mattering as the tree grew; it
now buys ROOM, and every run still opens with one shaft and re-earns the rest.
Floors already worked this way (`height_cap`); shafts were the outlier.

**The tenant market (2026-08-05).** Players no longer pick tenants: a vacant
tower floor refills itself 30 s later with a class-weighted market draw
(`sim/market.gd`, own rng — never the spawner's), and upgrading an occupied
floor prices its tenant out through an uncancellable move-out. `lease()` is
basement-only (parking). The old free-below-two-tenants rule is gone; the
market refilling for free IS the no-fail guarantee now.

Two numbers worth knowing before you touch the balance: run 1 yields **13
Blueprints**, measured on the real sim, because `combo` multiplies
`lifetime_earnings` — the field the conversion consumes — by ~7.6× on a
well-played 10-floor run. The tree's costs are denominated in that, and
`DEMOLITION_FLOOR` cannot be used to retune it (the offset subtracts before the
square root, so any value that reins in a strong player zeroes a weak one).
