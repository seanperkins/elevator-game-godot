ROUND 3 REVISION — responding to round-2 findings from codex, codex-regression,
claude-fable-skeptic-r2, claude-opus-skeptic-r2, claude-pentester-r2.

STRUCTURAL FIX THAT CLOSES FOUR FINDINGS AT ONCE (§7.2):
- Catch-up is now anchored on a SIM CLOCK (sim_wall_time, advanced only by executed
  ticks), never on saved_at. This closes: the missing atomic watermark (re-saving
  after catch-up with an old saved_at awarded the same hour twice); §8.3's
  "surrender to catch-up" having no interface into a saved_at-only entry point;
  the ~25% over-credit on desktop Chrome's throttled-but-not-stopped hidden tabs;
  and the overlapping-authority double-apply after a stall. saved_at is now a
  diagnostic field, not an economic input.
- In-session stalls NEVER route through the earnings-bearing catch-up model. Sim
  time simply lags wall-clock and deliveries land late. Routing jank through
  catch-up double-paid (analytic credit for passengers still in the discrete sim
  who then get delivered again), making income scale with jank.

§9 TOLERANCE — replaced the unachievable 1e-9 with two real tests:
- Test A (integrator exactness, 1e-9): §5.1 curves are now PIECEWISE-CONSTANT on
  1-simulated-minute buckets and the live spawner reads curve[floor(sim_minute)],
  so the integrated rate over whole minutes is the SAME FINITE SUM in both paths.
  1e-9 is legitimate there — on integrated rate/expected spawn count only.
- Test B (economic fidelity): +/-5% vs the mean of N seeded live runs, PLUS the
  property that actually matters: max over t0 of (catch-up/lived) <= 1.0 + delta,
  a no-exploit ratio bound.
- Rationale recorded: 1200x step mismatch is a different quadrature rule (7.9e-7
  for a pure daily sinusoid, 1.8e-3 for a rush ramp); stochastic floor is 1/sqrt(N)
  = 3.2e-4 even at 1e7 passengers; and live earnings vs a throughput ceiling are
  different quantities.
- Base offline rate pinned at 100% of the analytic model; Automation raises the
  CAP, not the rate (an upgradeable fraction would make offline differ from live
  by design and muddle the fidelity test).

§7.2 SUB-MINUTE REMAINDER: catchup_residual_seconds now persists and is carried.
Truncating meant a 45s app-switch earned zero forever; rounding up was a new
press-home-and-reopen free-money exploit. 120 cycles of 29s now equals one 58min
absence, and that is a named test.

§7.2 RESUME RECONCILIATION: on Hidden, the waiting passenger population is cleared
and folded into catch-up statistics; cars park idle. Otherwise every resume
restarted a discrete state whose patience timers are seconds-scale but hours old,
producing a mass-expiry event on the most common daily action. Stated explicitly
that catch-up wins over continuation state on the Hidden->Resumed path.

§7.1 VISIBILITYCHANGE MECHANISM: verified against Godot 4.7 web platform source
that only blur/focus are registered and nothing reads visibilityState. The plan
now names JavaScriptBridge.get_interface + create_callback under an
OS.has_feature("web") guard, with NOTIFICATION_APPLICATION_FOCUS_OUT as desktop
fallback, and a flag-and-consume rule since the JS callback fires outside the main
loop. §10.1 now requires the device check be done via PHONE LOCK, not app-switch.

§8.6 VALIDATION — rebuilt as a 7-step sequence:
- Structural/version-specific validation BEFORE migration; current-schema
  validation AFTER. Validating ids against today's data/ first would reject a
  legitimate v1 save whose ids migration exists to rename.
- TYPE-check before VALUE-check. is_finite() on {"cash": {}} raises during
  validation, i.e. before construction, so the refusal path never engages and the
  backup is never written -- the protection died before it ran.
- Collection size bounds checked before iterating; explicit known-key descent so
  unexpected nesting depth is structurally unreachable.
- Construction from an explicit key allowlist; never mass-assign into Object.set().
- REJECT rather than clamp on untrusted paths; clamping belongs only inside a
  migration step. Clamping shafts:99999 turns a hostile document into a legal save.
- Version below the migration floor / absent / non-integer now route through the
  same refuse-and-backup path.
- SAVE_MAX_BYTES checked before reading.

§8.6 WRITES_DISABLED LATCH: a refused load now latches EVERY write path (timer,
visibility-hidden, focus-out, quit, manual). Scoping it to "autosave" was defeated
in seconds -- a confused player switches apps to look up the error, firing the
immediate hidden-save. Import stays available while latched, since it is the
recovery path, and a successful validated import clears the latch.

§8.6 COALESCING SAVES: a save requested during an in-flight write sets a dirty flag
and runs one coalesced snapshot after. Blocking it discarded the most important
save in the design (timer save running -> buy upgrade -> background -> hidden-save
dropped -> tab killed -> pre-purchase state restored).

§7.3 IMPORT ENVELOPE: export is utf8_to_base64(JSON.stringify()); import is
base64_to_utf8 then JSON.parse_string. variant_to_base64/bytes_to_var forbidden on
BOTH sides -- banning it only on load left the trap armed on the export side, which
is where the pressure toward the compact-looking call comes from. Byte cap before
base64-decode, decoded-size cap before parse, backup + explicit confirmation,
single-flight against the save mutex.

§7.3 A2HS GUIDED MIGRATION: home-screen apps get their OWN storage container, so an
unguarded install prompt opens an empty building while the Safari save ages toward
ITP deletion -- the mitigation causing the loss it prevents. Now: export before
prompting, and offer paste-your-save on first standalone launch. Container
isolation added to the §10.1 device checks. Also: PWA icon fields must be
populated; ensure_cross_origin_isolation_headers stays false; service-worker
version skew makes the refusal path an ordinary post-deploy event.

§2.1 RELEASE-IN-PLACE: the rail's initial detent is now the CAR'S CURRENT ROW, not
the pressed row. Previously press-and-release on row R was surge, so dispatching to
the row under your thumb -- the most common intent -- required dragging away and
back on 32-unit rows. Also: pointer captured on drag-start and horizontal position
ignored, because a vertical thumb arc routinely exceeds the +/-22pt half-width and
would self-cancel the primary verb. Cancel is now drag past the board edge.
Corrected the units-vs-pt error: a row is ~16.5pt on an iPhone 15, not 32pt.

§3 SHAFT CEILING: 8 shafts stated as a board constant alongside the 40-row ceiling
(44pt is ~85 base units at 720 wide, so 8 edge-to-edge and realistically 6-7).
Capacity growth past the cap comes from cars-per-shaft, speed, capacity, doors.

§3 ERA INVARIANT DELETED: "era N+1 begins shorter in metres" was false for
Highrise->Megatower (1050m vs 560m) and Stratosphere->Orbital (480km vs 40km), and
impossible for Orbital at any integer row count (needs 0.5 rows). Replaced with the
true statement: the BOARD resets; absolute height is not monotone.

§5.3 ONE NO-FAIL RULE, NOT TWO: lobby-never-vacant made the free-re-lease guard
("no other tenanted row") unreachable, and made §9's recovery test unwritable
because its setup was forbidden. Now: re-leasing is free whenever zero rows are
tenanted; any row may vacate.

§8.5 NODE RECOUNT: ~1,672 nodes, not ~600 -- §2 gives each passenger a body, a
bubble, and a patience meter, so 40x12x3 = 1,440 for passengers alone. Car term is
bounded only because §3 now caps shafts. "Thousands, not hundreds."

§10.1 PROBE FIX MADE STRUCTURAL: `restored` is computed exactly once in _ready()
before any write and is immutable. Respecifying _ready() alone was insufficient --
_test_persistence() is also called from _on_tap(), so the first tap would read
after a same-session write and flip restored to yes, reproducing the exact false
positive the milestone was reopened for. Also: bbcode_enabled = false on the probe
readout, since §10.1 asked it to display a value from a file any other site on the
shared origin can write, in a scene §11 keeps permanently -- the plan was violating
its own newest rule (§8.4) in shipped code.

§10.2 CI: pin ALL actions incl. actions/* (the previous wording said "third-party"
and all four actions are first-party, so it pinned nothing); GUT pinned to a commit

move to deploy, else the per-job split breaks CI; run --import TWICE and require the
