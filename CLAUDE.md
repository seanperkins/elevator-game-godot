This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

An incremental/idle game about elevators (Godot 4.7, GDScript), built for **iPhone via GitHub Pages**. The primary target is the **threadless web export** — Pages cannot set the COOP/COEP headers Godot's threaded export needs. Anything added must work in mobile Safari and fit a 393pt-wide phone.

Two files are authoritative about what exists and why. **Read them before designing or editing:**
- `docs/superpowers/specs/2026-08-01-elevator-incremental-design.md` — the base design (some sections are out of date; the UI spec's §9 lists what).
- `docs/superpowers/specs/2026-08-02-ui-design.md` — current UI design (coords §3, ghost floor/shaft §3.4, input §4, verification §8).

Implementation plans and handoffs live in `docs/superpowers/plans/` (`HANDOFF.md` is a template for fresh sessions).

## Commands

```sh
godot                                # open editor
godot --headless --import            # import assets (×2 in CI)
godot --headless --export-release "Web" build/web/index.html   # web build
godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit   # run the whole GUT suite
```

- **Run a single test file:** `godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests/test_tenancy.gd -gexit`
- **Run one named test:** add `-ginclude="test_name"` (GUT test-name filter).
- **CI** (`.github/workflows/deploy.yml`): on push to `main` — install Godot 4.7 → run GUT → assert threadless export → build → deploy to Pages. Local GUT must pass before merging.
- **Dev-only override:** `godot -- --board=40x8` starts an oversized board for screenshots. Do not let this pattern into a shipped default.

## Architecture

Three hard-separated layers, sealed by the rule "sim never touches the scene tree":

```
data/ (JSON)  →  sim/ (pure RefCounted logic)  →  game/game_root.gd (the one owner)  →  view/ + ui/ (Nodes)
```

- **`sim/`**: all game logic, `extends RefCounted`, **no Nodes, no FileAccess**. Unit-tested headlessly via GUT. Talks upward only by signals emitted from `GameState`.
- **`data/`**: numeric coefficients (JSON) loaded at runtime. Never expression strings — running stored formulas is an eval.
- **`game/game_root.gd`** (entry: `game/game_root.tscn`) is the single owner: pumps the sim, saves, binds views. **Views never mutate logic**; they read state and emit signals.
- **view/ + ui/**: `Control` nodes that render sim state. Touching sim state from a view is a layering violation.

**The sim tick runs in a fixed, written order that is player-visible** (determinism + behavior depend on it):
`metrics.advance → spawn → move/doors → deliver → auto-dispatch → expire → tenancy → note_ticks`
Most important boundary: **deliver runs before expire**, so a passenger reaching exactly 0 patience as the doors open is delivered. Tests pin these orderings and cross-module invariants (e.g. `ElevatorCar.rows_per_tick` must equal `Upgrades.SPEED_BASE`) on purpose — do not weaken them.

The sim runs at **20 Hz** (SimClock accumulates Godot's default 60 Hz).

Core design invariants baked into the sim (see their docstrings):
- **No fail state** — cash floors at 0 (no debt); re-leasing is free while fewer than 2 rows are tenanted so a stranded player can always recover.
- **Rent is dead.** ALL money comes from moving people. A tenant's only value is the traffic it generates, so losing a tenant costs you that floor's fares.
- **Income to a floor is credited to the floor that *generated* the trip (`Passenger.source_row`), not the endpoint** — under directional traffic most trips have the lobby at one end.
