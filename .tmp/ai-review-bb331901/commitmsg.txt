Ban the force_fs_sync trap; A2HS tombstone; monotonic-clock contingency

Final verification fixes (fable skeptic, verified against the 4.7-stable tag and
this project's own built web glue).

The synchronous hidden-save fix is confirmed correct: the bridge callback really
does run inline on this build (the deferred branch is gated on PROXY_TO_PTHREAD,
which cannot engage in a threadless export), FS.syncfs is reachable through the
minified template, and JS being single-threaded means the handler cannot
interleave with a main-loop iteration.

- Banned JavaScriptBridge.force_fs_sync() on the hidden path. It is documented as
  "force synchronization of the persistent file system" so it is the first thing
  an implementer reaches for, but it only sets idb_needs_sync -- consumed by
  main_loop_iterate(), the loop that has stopped. Calling it looks like
  compliance while silently restoring the defect.
- Recorded that the synchronous guarantee is coupled to the threadless export, so
  a later move to the threaded template must revisit the section.
- Noted GodotFS.sync() refuses re-entry, so a hide racing the timer-save's sync
  must chain the pending promise rather than skip the flush.
- Monotonic-clock contingency: the HR-time spec permits performance.now() to
  pause across device sleep and iOS historically has. If the device check shows
  that, the Resumed boundary reads unix time like cold start; the epoch-domain
  watermark makes such credit deferred rather than lost.
- A2HS now writes a migrated-tombstone into the Safari-side save, so the copy
  left behind says "this building moved" instead of silently diverging.

The two regressions fable reported were both against pre-fix text and are already
closed by the concurrent edits: the residual double-count by committing
sim_wall_time = now, and the staleness/crediting conflation by having every
boundary credit and commit, which collapses elapsed back to hidden duration.
