# Floors you choose and invest in

**Status:** agreed, not yet built.
**Spec A of three.** B is signed floors and the basement; C is Demolish and
Blueprints. Built back to back, in that order.

Income is traffic, and traffic comes from tenants. So *which* tenant sits on a
floor is currently the largest untaken decision in the game: `relet()` restores
whatever was there, and every floor generates identical traffic at identical
hours. This spec makes a floor something you choose and something you invest in.

---

## 1. Why B comes before C

Prestige **resets the building**, so the reset path has to know the building's
shape. If signed floors arrive after prestige exists, the reset must learn about
a bottom floor retroactively — the retrofit the backlog argues is cheap at six
floors and expensive at forty. Build the shape, then build the thing that
resets it.

The basement is therefore unreachable in the shipped game for exactly the
duration of Spec B, testable by dev flag only. Spec C lights it with a Structure
node, which is the intended unlock.

## 2. Prerequisite: the stairs penalty is dead

`Economy.note_expiry(fare := 0.0)` applies a stairs penalty of one fare, and
`tests/test_economy.gd` covers it three ways. The only production caller —
`sim/game_state.gd:216` — passes no argument, so every real expiry deducts
`0.0 × 1.0 = 0`. The unit tests pass because they call `Economy` directly.
Nothing tested the wiring.

Fix: `economy.note_expiry(p.fare)`, plus a test **at the `GameState` level** that
runs a real expiry and asserts cash fell. A second unit test on `Economy` would
re-prove the half that already worked.

This lands first because §5 makes fares per-floor. Left alone, the penalty would
stay dead while silently acquiring a class multiplier.

## 3. Ownership: three facts, three lifetimes

| Fact | Owner | Lives until |
| --- | --- | --- |
| **class** | `Fitout` *(new)* | never — it is built into the floor |
| **kind** | `Tenancy` | the tenant leaves |
| satisfaction, move-out clock | `Tenancy` | the tenant leaves |

The rule this encodes: **things built into the floor persist; things built for
the tenant leave with them.** That is what makes replacing a tenant a real cost
rather than a free re-roll, and it is a line a test can sit on.

`Tenancy` keeps its current job unchanged. `Fitout` is new and small — a class
per floor and a price ladder — and is where amenities land in a later spec
without touching the tenancy loop.

Both are **per-run**: prestige resets class and kind along with the building.
Blueprints and the tech tree persist. Written here so Spec C inherits a decision
rather than making one.

### 3.1 One floor→index mapping

`Tenancy` and `Fitout` both index dense arrays from zero. Spec B makes floors
signed, and two containers discovering that separately is a bug farm.

`sim/floor_index.gd` (`FloorIndex`) owns the mapping alone:

```gdscript
var bottom_floor: int = 0
var count: int = 0

func contains(f: int) -> bool
func index_of(f: int) -> int      # -1 when out of range
func floor_at(index: int) -> int
```

`Building` owns one instance; `Tenancy` and `Fitout` hold a reference to **the
same** instance and each converts floor→index through it before touching its own
storage. Shared mapping, separate storage.

In this spec `bottom_floor` is always 0, so nothing changes behaviourally. That
is the point: Spec B moves one number, and a test asserts the two containers
agree about every floor.

This is the same discipline as `BoardCoords`' single row↔y transform, which is
what made the scrolling rework survivable.

## 4. What a tenant kind is

`data/tenants.json` **already exists and is dead.** It describes
`rent_per_minute` for a deli, a dentist and accountants — an income source
removed when rent was — and nothing loads it. This spec repurposes the file.

```json
{
  "kinds": [
    {
      "id": "office", "name": "Offices",
      "requires_class": 2, "lease_cost": 140.0, "base_fare": 4.0,
      "rate":     [24 floats],
      "inbound":  [24 floats],
      "outbound": [24 floats]
    }
  ]
}
```

- `rate` — trips per simulated minute generated by **one floor** of this kind,
  one bucket per simulated hour. Same shape and same bucketing as
  `traffic_walkup.json`, so the piecewise-constant property §5.1 relies on is
  preserved.
- `inbound` — share of that minute's trips that run **lobby → here**.
- `outbound` — share that run **here → lobby**.
- The remainder, `1 - inbound - outbound`, is **interfloor**: here → another
  tenanted floor.

Three parallel arrays rather than 24 tuples: readable in a diff, and the
sparkline reads them directly.

`sim/tenant_kind.gd` (`TenantKind`) parses one. `sim/tenant_catalog.gd`
(`TenantCatalog`) loads the file and answers `available_for_class(c)`. A
malformed file is refused whole, matching `Upgrades.load_defs` and
`TrafficSpawner.load_curve`.

### 4.1 The roster

Six kinds, two per class tier, differing in **shape** rather than magnitude. Two
kinds at the same tier that differed only in volume would make the choice a
subtraction.

| Class | Kind | Rhythm |
| --- | --- | --- |
| 1 | **Apartments** | out ~7am, in ~6pm; low volume, the mirror of an office |
| 1 | **Shops** | broad midday hump; interfloor-heavy |
| 2 | **Offices** | in ~8am, out ~5pm; high volume and spiky |
| 2 | **Gym** | twin peaks, early morning and evening; moderate |
| 3 | **Law Firm** | flat all day, low volume, high fare |
| 3 | **Clinic** | morning-weighted appointments, moderate, high fare |

A tower of nothing but offices has a brutal 8am and a dead noon. A mixed one is
smoother and never quiet. That is a genuine optimisation with no dominant
answer, and — the point of the whole spec — the up-peak / down-peak / interfloor
regimes real elevator engineering is organised around arrive as a *consequence*
of who leased, not as a mechanic bolted on.

### 4.2 A new building

Six floors, all class 1: floor 0 **Shops**, floors 1–5 **Apartments**. Fixed and
deterministic, so the starting day has a readable shape and no locked content is
on screen before the player knows what a class is.

## 5. Spawning: still one RNG draw per tick

`TrafficSpawner.spawn_for_tick(minute, sources)` where `sources` is an
`Array[TrafficSource]` — floor, `TenantKind`, fare multiplier — assembled and
**cached** by `GameState`, rebuilt only when tenancy or fitout changes.

1. `total = Σ source.rate_at(minute)`.
2. **One** Bernoulli trial against `total / TICKS_PER_MINUTE`.
3. Weighted pick of which source produced it.
4. Roll that source's inbound/outbound/interfloor mix for this minute.
5. Build the trip:
   - inbound → origin `LOBBY`, destination the source floor
   - outbound → origin the source floor, destination `LOBBY`
   - interfloor → origin the source floor, destination another tenanted floor,
     uniform
6. `fare = kind.base_fare × Fitout.fare_multiplier(source_floor)`

A trial per occupied row would be forty draws a tick at the cap and would make
the seed sequence depend on building height. The summed-rate form keeps the cost
of the RNG independent of how tall the tower is; the sum itself is arithmetic
over a cached array.

**`TrafficSpawner.REFERENCE_ROWS` scaling is deleted, not carried over.** It
existed because one building-wide curve described a six-floor building and had
to be stretched to fit a taller one. A per-floor rate summed over occupied
floors *is* that scaling — applying both would give a forty-floor tower
`40/6 ×` the traffic forty floors already generate. The kind rates are
calibrated so the §4.2 starting building totals roughly what
`traffic_walkup.json` gives today, which keeps the shipped opening unchanged and
gives the numbers a defensible origin.

`sim/traffic_source.gd` (`TrafficSource`) is the small `RefCounted` carrying
floor, kind and fare multiplier. It exists so the spawner never has to know
about `Tenancy` or `Fitout`.

**Fare is set by the floor that generated the trip**, whichever direction the
person travels. One rule, one lookup, and no argument about which endpoint owns
the fare. It also means a premium floor punishes failure harder, because the
stairs penalty is one fare.

### 5.1 Stated edge cases

- **A tenant on floor 0.** Inbound and outbound would both be lobby→lobby. Its
  `inbound` and `outbound` weights collapse into interfloor. The lobby stays
  leasable: `Tenancy`'s docstring is right that forbidding it makes the no-fail
  guard unreachable and its recovery test unwritable.
- **Fewer than two tenanted floors** produces no traffic. Unchanged.
- **Interfloor with one other tenanted floor** picks that floor. No rejection
  loop.
- **The RNG draw sequence changes.** Traffic after this lands differs from
  traffic before it for the same seed. Harmless, but it is why the save version
  bump is not optional.

## 6. Class

Three tiers. Every floor starts at 1. Flat price per floor — upgrading floor 20
costs what upgrading floor 2 costs; the constraint is cash, not a per-floor
ladder to track.

| Tier | Upgrade cost | Fare × | Unlocks |
| --- | --- | --- | --- |
| 1 | — | 1.00 | Apartments, Shops |
| 2 | $400 | 1.35 | + Offices, Gym |
| 3 | $2,500 | 1.80 | + Law Firm, Clinic |

Sized against the existing ladder: a shaft is $500, hall buttons $1,200, car
buttons $2,000.

The ladder lives in `data/tenants.json` beside the kinds, as a `classes` array
of `{ tier, cost, fare_multiplier }`. One file describes the whole leasing
domain, and the tier a kind requires is checked against the same list it is
tuned against — a kind requiring a tier the ladder does not define is a
malformed file, refused whole.

**The fare multiplier is why the upgrade button is not inert on a tenanted
floor.** Class gates leasing, and leasing only happens on vacancy — so a class
purchase with no live effect would pay nothing until the tenant left, making it
a button you rationally never press except in a crisis. The multiplier pays
immediately; the unlock pays later.

Purchases go through `GameState`, refused there rather than merely greyed —
same rule as `Upgrades.purchase()` and `set_policy()`, because a disabled button
is bypassed by two taps queued during a stalled frame.

## 7. Input: a hall column

`view/hall_column.gd` (`HallColumn`) — one `Control` spanning the full board
height and the hall region (x < `FloorRow.STRIP_RIGHT`), reusing `Gesture` and
`PointerEvents` exactly as `ShaftColumn` does.

- **TAP** → `floor_selected(floor)`
- **PAN** → `pan_requested(delta)`

A column rather than `_gui_input` on each `FloorRow`: one input path, one
gesture implementation, dragging on the left still pans the board, and a drag
that crosses a row boundary cannot become ambiguous. Its local y is board y, so
a touch goes straight to `y_to_floor` with no offset arithmetic — the property
that made `ShaftColumn` correct after scrolling.

`FloorRow`'s children are already `MOUSE_FILTER_IGNORE`, so the column overlays
them without stealing anything that was working.

## 8. The panel

`ui/floor_panel.gd` (`FloorPanel`) — a bottom sheet over the board, inset by
`SafeArea`, all targets 44pt.

```
FLOOR 4                      class ★★☆
────────────────────────────────────────
Offices                    ▓▓▓▓▓▓░░ 71%
  6a      12p       6p      12a
  ▁▁██▃▁▂▃▂▁▁██▁▁▁▁▁▁▁▁▁▁▁
  █ to floor   ▓ to lobby   ░ between

UPGRADE CLASS  ★★☆ → ★★★        $2,500
  unlocks Law Firm, Clinic · fares ×1.8

(roster, only when vacant)
```

Sections:

1. **Header** — floor number, class, tenant name, satisfaction bar.
2. **Sparkline** — the sitting tenant's day. Absent when vacant.
3. **Upgrade class** — price and what it buys. Disabled at tier 3 or when
   unaffordable, and refused by the sim regardless.
4. **Roster** — **only when the floor is vacant.** Each kind with its sparkline
   and lease price; kinds above the floor's class shown greyed with the class
   they require, so the upgrade has a visible reason.

You choose who moves **in**, not who moves **out**. Tenant churn stays driven by
satisfaction, so the move-out clock keeps its teeth and the panel cannot be used
to dodge it.

`view/day_sparkline.gd` (`DaySparkline`) — a `_draw()` control, 24 buckets, bar
height proportional to rate, each bar split vertically into up to three coloured
segments by that minute's mix. It shows volume and direction at once, which is
what makes two kinds at the same tier comparable.

### 8.1 `ui/relet_confirm.gd` retires

It was the one documented 44pt exception, and it existed only because a 16pt row
could not be a touch target. Rows are a fixed 88 units now and this panel
supersedes it. Deleting it removes the last survivor of the fit-to-screen era.

## 9. The no-fail guarantee, restated

Unchanged in spirit, sharpened in statement: when `tenanted_count() < 2`,
**leasing costs 0 for any kind on the roster.**

The **class gate, not the price**, is what stops that being exploitable — a
class-1 floor only ever offers class-1 kinds, whatever the player can afford.

Test: a player holding $0 with one tenant can always lease and recover.

---

## 10. Save

`SaveCodec.VERSION` 1 → 2. Each row gains `kind` and `class`.

**A v1 save migrates rather than being refused.** The standing rule — refuse
whole rather than half-apply — exists for fields that cannot be inferred.
These can: absent `class` is 1 and absent `kind` is `apartments`, which is
exactly what a v1 building was. Refusing would wipe a save that is currently
being played on a phone to avoid a risk that does not exist here.

Kind is restored by id through the catalog; an unknown id falls back to
`apartments` rather than leaving the row kindless. Class is clamped to the
ladder, so an edited save cannot grant tier 4.

## 11. Tests

**Sim**

- `FloorIndex` round-trips every floor; `Tenancy` and `Fitout` agree on the
  mapping for every floor.
- `TenantCatalog.available_for_class` returns exactly the tiers at or below.
- A malformed `tenants.json` is refused whole.
- Offices at 8am produce mostly **inbound**; Apartments at 8am mostly
  **outbound**. The mirror is the whole point of the feature, so it is asserted
  directly rather than inferred from a total.
- Spawning performs **exactly one RNG draw per tick** regardless of floor count
   — the guard against an O(rows) regression.
- A tenant on floor 0 never generates a lobby→lobby trip.
- Fare reflects the generating floor's class, in both directions of travel.
- Class purchase is refused by the sim when unaffordable or at max.
- Leasing is free below two tenants; a $0 player with one tenant recovers.
- **A real expiry in `GameState` deducts cash** (§2 — the seam, not the unit).

**Save**

- v2 round-trips kind and class.
- A v1 save loads, every row at class 1 and `apartments`.
- An unknown kind id falls back; an out-of-range class clamps.

**View**

- `HallColumn` tap selects the floor it looks like **after scrolling** — a board
  wrong by a scroll offset is self-consistent on screen and catastrophic in
  play.
- A drag on the hall column pans and does **not** select.
- The roster is hidden while tenanted, shown when vacant, and a floor with a
  running move-out countdown counts as tenanted.
- `DaySparkline` draws 24 buckets and its segment heights match the mix.

## 12. What must not regress

Every constraint that was a review finding stays a constraint. The ones this
spec is closest to:

- The sim never touches the scene tree; `Fitout`, `TenantCatalog` and
  `TenantKind` are `RefCounted`.
- One row↔y transform, and now one floor→index mapping, each with all consumers
  going through it.
- Zero-delta and unaffordable purchases refused by the sim, not merely greyed.
- `GameState.relet` reads the cost **before** reletting. Leasing a kind must
  preserve that order: `relet_cost` derives from `tenanted_count`, which
  leasing increments.
- The fixed tick order in `GameState`'s docstring is unchanged. Nothing here
  adds a phase.
- 44pt touch targets. The one exception retires with `relet_confirm`.

---

## 13. Deliberately not in this spec

- **Improvements** (tenant-scoped throughput) and **amenities** (floor-scoped
  tolerance). The persistence rule in §3 and the panel's section order leave
  room for both; neither is stubbed.
- **Tenants who will not mix.** A layout constraint on top of a choice that does
  not exist yet.
- **Per-kind patience.** Fares vary by kind and class here; patience stays
  building-wide until there is a reason it should not.
- **Reputation gating which kinds are available at all.** Class is a per-floor
  gate; a building-wide one is a second, and one is enough to learn from.
- **Offline earnings.** Still §9.1, still unsettled, still deliberately unbuilt.
